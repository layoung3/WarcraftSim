# Rogue Thousand Cuts: historical lifetime and live Energy costs

## Bounded source contract

The historical tooltip and implementation at `gunba/wow-forever-sim@1cc5ae1e9abdbf941b7326d2d90421822dce31ba` support one caster-owned ten-second benefit, refreshed on each qualifying tick including at five stacks, reducing Backstab/Hemorrhage by three Energy per stack. The implementation expires the old benefit at `now >= expiry`; a tick at that boundary starts one new stack. These are historical simulator receipts, not current-server certification. See the companion source receipt for exact paths and hashes.

This stage retains the local positive owned periodic Rupture trigger and Backstab/Hemorrhage completion consumption. The pin instead reacts to periodic/direct notifications without positive-damage or landed gating. Zero-damage Rupture remains excluded locally; eligible miss/avoidance and landed-zero executions still consume. Invalid, unspent or duplicate completion observation can still clear the benefit; payment-validity and callback migration are explicitly deferred. `CastCompletionProcessed` is not proof of payment. No miss refund or landed-only policy is introduced.

## Implementation and compatibility

`RogueThousandCutsState` owns the existing AuraManager stacking aura and binds the intended eligible flat Energy component by reference after validating spell identity, resource, percentage flag and original 60/35 amount. Ambiguous components are not selected. Restoring cost derives from the captured base, never cumulative subtraction. Unrelated, percentage, multiple-resource and additional-consumption components keep the existing aggregate rules. Replacing a definition/component does not accidentally grant its replacement the captured modifier.

A small optional executor cost policy reconciles current state immediately before start affordability and actual spending. Only the two ability-readiness paths in PriorityRotationExecutor use its quote; the next-swing raw-cost path remains unchanged. A forecast crossing expiry recomputes restored-cost affordability using detached costs from the same current time, without advancing resources to the candidate or changing current aura/price state. No schema, dependency, global scheduling or processor-order change is made. The null-policy path uses the existing calculator.

The Rogue observer synchronizes gains, expiry and consumption immediately. It removes expired state before regrant and re-reads current ownership rather than clearing a newer benefit from stale notifications. Dedicated `thousand-cuts` / `thousand-cuts-benefit` identifiers avoid Rupture finisher handling. Other UpdateRotation mechanics remain unchanged.

Aura applications/removals add real timeline rows and ordinary aura-sensitive rotation wake-ups. The existing regeneration observer refreshes balances at the current timestamp and reinstates the same configured rate (including Adrenaline Rush). Talented event streams are intentionally not asserted identical to the old implementation. No absent/zero-rank aura state is allocated. This is the current spellbook cost contract, not live modifier hot-reloading: mutating the same bound component amount after construction is overwritten by canonical-base synchronization. This does not add live talent hot-reloading, strict Subtlety admission, filler ranks, UI/presets or optimized-build claims. Aggression, Cold Blood, Premeditation and Hemorrhage damage tuning are unchanged.
